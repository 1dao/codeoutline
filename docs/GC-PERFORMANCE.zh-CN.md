# GC 生命周期与性能记录

首次加载项目时使用 `setpause=100`、`setstepmul=500`，覆盖缓存解码、基础索引、符号表准备与保存。完成后恢复调用前的参数；失败和取消也会恢复，不把加载期参数留给后续编辑器查询。

Agent 分析允许较长耗时，每次结束后执行完整 GC。LSP 等外部 worker 请求则先通过 RPC/post 回复，再注册单次 timer，空闲时推进一轮 GC 的一个步骤；未完成才注册下一次 timer。每个 worker 最多保留一个待执行 timer，新请求到来时撤销，挂起的前台任务存在时不回收，关闭时取消。没有待执行回收时仍保留原有空闲 GC，处理项目淘汰等情况。

timer 在 worker 的 `__init` 中初始化，不创建额外线程或 GC 协程。默认延迟 1 ms、步长 4096。延迟只是最早到期时间，不保证实际 1 ms 唤醒；步长是 LuaJIT 的工作量参数，不是耗时上限。单个 GC 步骤或原子阶段仍不可抢占。

## 配置

默认无需编辑器环境变量。可选覆盖：

| 环境变量 | 默认 | 用途 |
|---|---:|---|
| `CODEOUTLINE_LSP_GC_EVERY` | `1` | 每多少次 worker 回复触发回收；`0` 禁用主动调度，保留原有空闲 GC |
| `CODEOUTLINE_LSP_GC_DELAY_MS` | `1` | 回复后 timer 延迟，毫秒 |
| `CODEOUTLINE_LSP_GC_STEP_KB` | `4096` | 每次空闲回收的工作量参数 |
| `CODEOUTLINE_MEMORY_POLICY` | `startup` | `default` 禁用加载期参数切换 |
| `CODEOUTLINE_AGENT_GC` | `1` | `0` 禁用 Agent 操作后的完整 GC |

早期实验的 `CODEOUTLINE_LSP_GC_MODE` 不再选择回收模式：worker 返回后统一使用分步回收。0 ms timer 的实际延迟取决于原生运行时；本提交不包含原生轮询修改，建议使用默认 1 ms，不将 0 ms 当作提速保证。

## Windows 实测（2026-10-30）

真实大型项目包含 57,303 个文件、815,744 个声明。使用独立服务进程和索引副本，原生 LuaJIT GC64、8 个解析线程；性能场景顺序执行。以下为本机单轮结果，不代表所有项目的硬性上限。

| 场景 | 耗时 | 结果 |
|---|---:|---|
| 全量生成 | 23.64 秒 | 0 解析失败，成功保存 34.58 MiB 索引 |
| MCP 缓存启动 | 11.23 秒 | `cacheLoaded=true`，0 文件重解析 |
| LSP 启动到导航就绪 | 11.75 秒 | 新进程加载已有缓存，操作系统磁盘缓存可能已热 |

| 请求 | 次数 | P50 ms | P95 ms | 最大 ms | 超过 1 秒 |
|---|---:|---:|---:|---:|---:|
| 定义跳转 | 1200 | 40.6 | 187.6 | 576.4 | 0 |
| 连续输入补全 | 624 | 45.6 | 339.1 | 435.5 | 0 |
| 补全后跳转 | 16 | 53.9 | 280.8 | 280.8 | 0 |

| 独立进程场景 | 空闲 Private Bytes MiB | 空闲 Working Set MiB | Private Bytes 峰值 MiB |
|---|---:|---:|---:|
| 全量生成及随后 32 次 Agent 查询 | 903.25 | 900.89 | 1364.82 |
| 缓存启动及 32 次 Agent 查询 | 905.89 | 907.19 | 946.58 |
| 1200 次跳转 | 954.65 | 955.39 | 1015.39 |
| 624 次补全及 16 次跳转 | 1082.73 | 1081.76 | 1124.71 |

Agent 场景空闲 10 秒，LSP 场景空闲 30 秒；末尾均剩 2 个线程。峰值包含启动/生成及后续查询。64 次 Agent 查询的返回哈希与既有结果一致；包含完整 GC 后，单次最大耗时 2.44 秒。

原有空闲 GC 在同一查询集上的 1200 次跳转：空闲 Private Bytes 为 1112.24 MiB、峰值 1264.42 MiB。当前分步 timer 方案对应为 954.65 / 1015.39 MiB；P95 从 131.4 ms 增到 187.6 ms，仍保持该组所有跳转小于 1 秒。对照来自同一会话的不同运行，不能把全部差异解释为可重复的固定收益。

跳转覆盖 104 个位置、100 个文件和 7 种语言，模拟打开/关闭文件，前 400 次访问热位置、后 800 次轮换全部位置。补全使用未保存草稿连续改变前缀。124 次补全返回 `isIncomplete`，受查询预算和条数限制，不能据此声称补全结果完全；补全后的跳转通过位置校验。

本轮是实际 stdio 协议回归，没有在目标编辑器中自动点击验证。Agent/MCP 与 LSP 为独立进程，未测同一个 Lua 状态中 Agent 完整 GC 与 LSP 并发排队的情况。索引结构没有改变，也没有将降低工作集当作提交量已经归还的证据。

## 提交范围验证

将暂存内容单独导出，使用原有原生运行时和子模块 HEAD 的测试资源执行，未依赖本地 C 修改或独立的系统头参数提示修复。核心 390 项、LSP 195 项、稳定性 31 项全部通过；`npm test` 为 77 通过、1 跳过、0 失败，覆盖原生/纯 Lua 扫描及官方 MCP SDK。

另外在导出的暂存版本上清除 GC 实验环境变量，用隔离用户目录和缓存副本启动真实 LSP。16 次跳转返回与既有位置一致，最大耗时 609 ms，确认默认配置启用的回收策略可在原运行时上运行。
